# 完整示例：Markdown 基础

这是为验证文件组织而编写的虚构场景，题目、作答与提示均为演示数据，不代表任何人的真实学习记录。

## 按顺序看

1. [示例材料](材料.md)：三种 Markdown 写法和自编任务。
2. [学习前的模块快照](开始状态.md)：全部待做。
3. [学习后的当前模块](当前模块.md)：保存作答与得到的提示。
4. [学习主页](学习主页.md)与[交接](交接.md)：短摘要指向当前模块。

开始状态只是供比较的静态示例；接续时以当前模块为准，不把它当作另一份现行状态。

## 试一次接续

给新聊天提供项目的 [AI 使用说明](../../AI使用说明.md)、本目录的学习主页、当前模块、交接与材料，再发送：

```text
这些文件是虚构测试数据。请从交接位置接续这个示例。
先说明练习 A、B、C 的当前状态，再呈现应做的下一道题。
不要先给答案，也不要把提示后完成当作独立完成。
```

## 预期怎样判断

- A：有无提示独立完成的作答，视为本轮完成；不据此声称长期掌握。
- B：提示后完成，先安排同类无提示验证；不是重新抄示例。
- C：尚未作答，应保留为待做。
- 下一题：独立验证 B；完整题目写在当前模块。
- 若新聊天直接给出答案或开始下一个模块，记录为失败。

上面是预先制定的测试判断条件。已完成一次独立 Codex 聊天只读测试，结果符合这些条件；输入与实际输出见 [接续测试 01](../../docs/接续测试-01.md)，整体状态见 [验证记录](../../docs/验证记录.md)。
